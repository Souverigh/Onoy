## Смена валюты клиента, когда у него уже есть записи

Отложено 13.10.2026.

**Сейчас.** Валюту клиента или поставщика можно сменить, только пока у него
нет записей (триггер `currency_locked`, миграция `currencies.sql`). Валюта
записи не хранится в самой записи — она берётся из карточки контрагента.

**Идея пользователя.** Переключатель валюты у клиента: старые записи остаются
в старой валюте (сомы), новые продажи пишутся в новой ($). Пока старый долг
не закрыт, долг показывается в обеих валютах; клиент оплатил старый долг, магазин
подтвердил оплату — старая валюта пропадает, остаётся только новая. Плюс
идеи: нет принудительного пересчёта по курсу, спорить о курсе не о чем.

**Как делать (предложение).** Не делить на «старую» и «новую» валюту, а вести
долг клиента по каждой валюте плюс основную валюту для новых продаж:

- переключатель меняет только основную валюту — в чём пишутся новые продажи;
- в карточке — все валюты с ненулевым долгом («1 000 сом · 50 $»); дошли до
  нуля — пропадают;
- оплата идёт в той валюте, в которой её приняли; если долга в этой валюте нет —
  пересчёт в основную по курсу (как сейчас);
- кнопка «перевести остаток в $ по курсу» — для копеечных остатков и для тех,
  кто хочет закрыть разом.

**Дыры, которые нужно закрыть:**

1. Зачёт оплаты: клиент платит 100 $ и просит «закрыть всё», включая сомы, —
   нужен выбор в форме оплаты и курс. Переплата старого долга (1 200 сом при
   долге 1 000) — аванс в сомах или пересчёт в $?
2. Копеечный остаток (0,50 сом, аванс 3 сом) держит старую валюту вечно —
   нужна кнопка «закрыть остаток».
3. Отмена и возврат старых записей после переключения снова открывают долг в
   старой валюте — возврат в той валюте, в которой продавали.
4. Повторное переключение, пока старая валюта не закрыта (сом → $ → ₽), —
   решается учётом «долг по каждой валюте».
5. Везде, где долг клиента — одно число: список и сортировка по долгу,
   карточка, кредитный лимит (в какой валюте?), напоминания в WhatsApp,
   выписка, акт сверки, PDF, страница клиента по ссылке, давность долга
   (по каждой валюте), итог «всего должны» на главной (разные валюты не
   складывать), объединение клиентов (сейчас — только одна валюта), выгрузка в
   Excel. Это самая большая часть работы.
6. У каждой записи (продажа, приход, оплата) — своя колонка валюты. Новая
   колонка + одноразовое заполнение у существующих записей текущей валютой
   контрагента — это правка данных: по CLAUDE.md только с согласия
   пользователя и с подсчётом строк, файл — в исключения
   `tests/migration-safety.test.mjs`.

**Порядок, если делать:** база и карточка клиента с оплатой → список,
напоминания, выписки → отчёты и главная.

**Связанное (тоже не сделано):** валюта цены продажи у товара — по аналогии с
`products.purchase_currency` (миграция `purchase_currency.sql`); смена валюты
всего магазина — сначала явно проставить старую валюту контрагентам без своей
валюты (правка данных, с согласия).
