# Oŋoy — План рабочего пилота на 7 дней

## 1. Цель спринта

За 7 дней собрать **рабочий пилот Oŋoy для первого реального клиента**.

Это не финальный SaaS и не полноценная замена 1С. Цель пилота — проверить три главные цепочки:

1. **Приход товара по фото накладной**
2. **Продажа по фото рукописной накладной**
3. **Оплата по фото/скриншоту MBank-чека**

Главный принцип:

> **Пользователь фотографирует документ, проверяет результат и подтверждает. Вся сложная ERP-логика работает внутри системы.**

---

## 2. Что должно работать к концу недели

Пользователь должен уметь:

- войти в Oŋoy;
- открыть клиентов, поставщиков и товары;
- видеть остатки;
- видеть долги клиентов и поставщика;
- создать клиента и товар вручную;
- сфотографировать или загрузить накладную поставщика;
- получить распознанные позиции через ADRE;
- исправить ошибки распознавания;
- задать продажные цены;
- оприходовать товар;
- сфотографировать рукописную накладную клиенту;
- подтвердить клиента и товары;
- провести продажу;
- загрузить MBank-чек;
- подтвердить оплату;
- видеть историю основных операций.

---

## 3. Что НЕ делаем за эту неделю

Чтобы реально закончить пилот за 7 дней, не включаем:

- полноценную бухгалтерию;
- налоговую отчётность;
- зарплаты и HR;
- CRM-воронку;
- сложные роли пользователей;
- банковские API;
- полноценный WhatsApp Business API;
- синхронизацию с 1С;
- сложную аналитику;
- десятки типов документов;
- полноценный offline-first;
- сложную систему филиалов и складов;
- автоматическое проведение без проверки пользователя;
- идеальную кыргызскую локализацию.

# День 3 — ERP Core

## Приход товара

Сделать ручную операцию:

- выбрать поставщика;
- добавить товары;
- количество;
- закупочная цена;
- продажная цена;
- итог;
- подтвердить.

После подтверждения:

- создаётся purchase;
- создаются purchase_items;
- увеличиваются остатки;
- увеличивается долг поставщику.

## Продажа

Сделать ручную продажу:

- выбрать клиента;
- добавить товары;
- количество;
- цена;
- итог.

После подтверждения:

- создаётся sale;
- уменьшается склад;
- увеличивается долг клиента.

## Оплата

Поддержать:

- получили от клиента;
- оплатили поставщику.

После подтверждения долг пересчитывается.

## Источник истины

### Долг клиента

`Продажи - оплаты клиента = долг`

### Долг поставщика

`Закупки - оплаты поставщику = долг`

### Остаток

`SUM(inventory_movements.qty_delta)`

## Результат дня

Oŋoy уже работает как простая ручная ERP без ADRE.

`ламп хороз 12`

`Horoz LED 12W`

`ламп хороз 12 -> Horoz LED 12W`

Если есть bank reference:

`organization_id + bank_reference`

`date + amount + sender + receiver + file hash`

---

## 8. Надёжность данных

### Commit только через transaction

Например продажа:

```text
sale
+
sale_items
+
inventory_movements
+
document link
+
audit
```

Либо сохраняется всё, либо ничего.

### Idempotency

Каждый commit должен иметь:

`Idempotency-Key`

Повторный клик не должен создавать вторую продажу.

---

## 9. ADRE в первой версии

ADRE не меняет ERP напрямую.

Он только:

1. классифицирует;
2. распознаёт;
3. предлагает данные;
4. предлагает совпадения.

Пользователь всегда подтверждает критическую операцию.
