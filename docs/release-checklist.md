# Выкладка новой версии

Правило с 06.10.2026. В тот день утром после выкладки перестали записываться
все оплаты («Введите сумму больше нуля»), и это заметили только в магазине.
Причина: формы «Клиент принёс деньги» и «Я заплатил поставщику» не отправляли
направление оплаты. Исправлено в ba29232.

## Когда

Только вечером, после закрытия магазина. Днём не выкладывать, даже мелочь.

## До выкладки

1. `npm run check`: тесты, проверка типов, сборка.
2. Если в версии есть новая миграция, её сначала применяет пользователь, после
   бэкапа базы. Только потом выкладывается код. Код рассчитан на то, что
   миграция уже в базе.

   С 21.10.2026 это проверяет сама сборка на Vercel
   (`scripts/check-migrations.mjs`): спрашивает у базы `app_schema_version()`,
   и если в коде есть миграция новее — сборка падает с текстом «ВЫКЛАДКА
   ОСТАНОВЛЕНА», на сайте остаётся прошлая версия. Применили миграции —
   Vercel → Deployments → упавшая сборка → Redeploy.
   Каждая новая миграция заканчивается строкой с её номером (иначе `npm test`
   подскажет, что добавить):
   `create or replace function public.app_schema_version() returns text language sql immutable set search_path='' as $$ select '<номер из имени файла>' $$;`
   Обойти один раз, если база недоступна, а выложить нужно срочно: переменная
   `SKIP_MIGRATION_CHECK=1` в Vercel (потом убрать).

## После выкладки: 5 действий на телефоне

Делать на настоящем телефоне, на рабочем аккаунте, на маленьких суммах.
Каждую запись потом отменить.

| № | Действие | Работает, когда |
|---|----------|-----------------|
| 1 | Продажа по фото накладной | Экран «Продажа записана», долг клиента вырос |
| 2 | «Клиент принёс деньги» | «Записано», долг клиента уменьшился |
| 3 | «Я заплатил поставщику» | «Записано», долг поставщику уменьшился |
| 4 | Отмена записи (любой из трёх выше) | Запись помечена «отменена», долг вернулся |
| 5 | «Итог дня» | Цифры открываются, в кассе нет минуса из-за проверки |

Всё работает: написать в чат «5 действий проверил, всё работает».

Что-то не работает: сразу вернуть прошлую версию (Vercel → Deployments →
прошлая → Promote to Production / Instant Rollback) и написать Кулчоро.
Миграции при этом не откатывать: они только добавляют, старый код с ними
работает.
