## Что это

**Depter** — веб-приложение для магазинов стройматериалов в Кыргызстане:
цифровая тетрадь долгов клиентов и поставщиков с фото-основанием каждой
записи. Кодовое имя репозитория/пакета — `ongoy` (внутреннее, в интерфейсе
не показывается). ТЗ (обновлённая версия, Этап 1) лежит вне репозитория —
`C:\Users\erzha\Documents\ONOY\Depter — ТЗ, Этап 1.docx`; если нужно свериться
заново, читать через docx-скилл (Read не читает бинарные .docx напрямую).

Стек: Next.js 16 (App Router, TypeScript), Supabase (Postgres + Auth + Storage),
Vercel-деплой. Никакого service-role в приложении — всё через RLS и
security-definer RPC. Перед работой с API Next.js — читать
`node_modules/next/dist/docs/` (см. AGENTS.md: версия отличается от обучающих
данных; например, лимит тела server action — 1 МБ по умолчанию).

Пользователь пишет по-русски; интерфейс приложения — на русском.

## Что сделано (в хронологии, все пункты — рабочие, покрыты тестами где есть логика)

1. **Foundation** (до первой сессии): справочники, RLS, мультитенантность,
   `commit_purchase/sale/payment` — сумма долга вводится вручную, долг
   меняется сразу, без ожидания.
2. **Долги Этапа 1**: фото обязательно для прихода/продажи, необязательно
   для оплаты; сторно (отмена записи с комментарием, не удаление); заявки
   клиента «Я оплатил» + публичная страница `/c/[token]` без входа; итог дня
   (`/day`, живой пересчёт); акт сверки с печатью и PDF; напоминание —
   `wa.me`-ссылка.
3. **ADRE** (`src/lib/adre/`): распознавание фото через Gemini, фон через
   `after()`, статусы документа (ожидает/распознаём/оцифрована/расхождение/
   ошибка), экран `/documents`. Ключ — только в Vercel Environment Variables,
   НЕ в Supabase (Edge Function делали и откатили по просьбе пользователя).
4. **Синонимы контрагента**: `src/lib/match.ts` (коэффициент Дайса, без
   pg_trgm) + баннер на `/documents/[id]`.
5. **Оплата по квитанции**: синхронное распознавание чека до подтверждения,
   подсказка клиента по имени отправителя.
6. **Мгновенная сверка суммы прихода/продажи**: при выборе фото —
   распознавание сразу на той же странице, сравнение с введённой суммой,
   кнопка «Подставить».
7. **Фирменный PDF**: `@react-pdf/renderer`, шрифт PT Sans в `public/fonts/`,
   регистрируется по HTTP.
8. **Нормализация извлечённых данных**: `src/lib/adre/normalize.ts`.
9. **Тип документа по ADRE** на `/documents/[id]` + предупреждение при
   несовпадении с выбором продавца.
10. **Парсинг суммы с пробелом-разделителем тысяч** (`decimalInput`).

### Сессия 26.09.2026

11. **Форма прихода показывала клиентов вместо поставщиков** →
    `invalid_supplier`. Список в `operation-form.tsx` выбирался по `direction`
    (нужен только оплате). Исправлено: приход → suppliers, продажа → customers.
12. **Гонка «нажал Подтвердить, пока фото проверяется»**: кнопка заблокирована
    на время сжатия/загрузки/распознавания фото (`Submit disabled`, текст
    «Проверяем фото…»); после проверки файл повторно не отправляется
    (у input снимается `name`, сервер берёт `document_id`); защита от
    опоздавшего ответа по старому фото (`photoRequest` ref).
13. **Понятные ошибки фото**: `photo_used` («фото уже приложено к другой
    записи…») и `photo_upload` вместо общего «приложите фото».
14. **Скорость и стоимость Gemini** (`src/lib/adre/gemini.ts`):
    `thinkingConfig.thinkingLevel=low` и `mediaResolution=MEDIA_RESOLUTION_MEDIUM`
    (по документации Google для документов качество на medium насыщается);
    при HTTP 400 — автоматический повтор без этих полей с
    `console.warn("callGemini: tuned request rejected…")`. **Живым вызовом не
    проверено** — имена полей REST generateContent взяты по памяти/доке
    Interactions API. Если в логах Vercel есть это предупреждение — поправить
    имена полей. В оценку стоимости добавлены `thoughtsTokenCount`.
15. **Кеш распознавания** (`src/lib/adre/recognize.ts`, `recognizeWithCache`):
    ответ Gemini сохраняется в `document_extractions` сразу
    (`cache_extraction`, `payload.kind` = `invoice` | `receipt`), поиск — по
    `file_hash` документа (все документы с тем же фото). Один платный вызов
    на одно фото: повторный выбор, фоновая оцифровка после подтверждения,
    квитанция (раньше распознавалась дважды). Стоимость/задержка пишутся
    только в строку кеша; `/documents/[id]` берёт latency из последней
    строки, где она есть. Встроенный кеш Gemini не применим (минимум 4096
    токенов, наш запрос ~300 + картинка).
16. **Сжатие фото в браузере** (`src/lib/shrink-image.ts`): до 2000 px по
    длинной стороне, JPEG 0.85, файл подменяется прямо в `<input>` через
    `DataTransfer`. Причина — лимит тела server action 1 МБ; дополнительно
    `experimental.serverActions.bodySizeLimit = "4mb"` в `next.config.ts`
    (запас для HEIC и т.п.; выше 4.5 МБ не пропустит Vercel).
17. **Повтор одного фото — настройка магазина** (`/settings`, галочка «Не
    принимать одно фото накладной дважды», по умолчанию вкл). Вкл →
    `document_in_use`, продавец видит это уже при выборе фото. Выкл → создаётся
    новый документ с тем же хешем, запись проходит, предупреждение в форме и
    `?duplicate=1` на `/money`. Сторнированные записи и отклонённые заявки фото
    не занимают. Свободный (ни к чему не привязанный) документ с тем же фото
    переиспользуется, в т.ч. со сменой `kind`.
18. **Похожие записи по содержимому** — только предупреждение, не блокирует
    (решение пользователя). `src/lib/adre/fingerprint.ts`: sha256 от
    отсортированных позиций (название упрощено до букв/цифр, qty, price) +
    итог; считается при каждом распознавании накладной (в т.ч. из кеша) и
    пишется `set_document_fingerprint`. `find_similar_records` — два
    индексных поиска, без перебора: тот же отпечаток (кроме того же файла
    фото) и тот же контрагент+сумма за **30 дней** (решение пользователя),
    не сторнированные, до 3 шт. Форма вызывает `findSimilarRecords` с паузой
    400 мс при изменении фото/контрагента/суммы и показывает список со
    ссылкой на документ. Только приход/продажа, для оплат нет. Записи,
    распознанные до миграции 10, отпечатка не имеют.
19. **Мобильная навигация** (≤560 px, `shell.tsx`, `globals.css`): внизу три
    раздела (Главная, Клиенты, Поставщики), остальные (Деньги, Итог дня,
    Заявки, Документы, Настройки, Выйти) — в меню-бургере в закреплённой
    шапке; счётчик документов на проверке на бургере. Проверено скриншотом
    headless Chrome на 390 px через `/preview` (бургер виден и в предпросмотре,
    ссылки ведут на `/preview`).
20. **«Сторно» → «Отменить запись»** во всём интерфейсе (метка «отменена»,
    кнопка «Да, отменить запись», PDF акта сверки). В коде/БД остаётся `reverse_*`.
21. **`total_computed` считается в коде** (`normalize.ts`, `computeTotal`):
    Σ qty×price в тийынах; строка без читаемых qty/price берёт свою `sum`;
    без строк — значение модели. Работает и для кеша (нормализация на
    чтении). Модель поле по-прежнему возвращает (схема), но оно перезаписывается.
22. **Карточка клиента/поставщика — рабочая история** (`[kind]/[id]/page.tsx`):
    список до 20 записей, у каждой «Фото» (→ `/documents/[id]`) и «Отменить»
    (→ `/money/reverse/...?back=/customers/<id>`; после отмены — возврат в
    карточку с кнопкой «Записать правильно»). Заявки — «Рассмотреть» → `/claims`.
    Кнопки «Продажа/Приход» и «Оплата» открывают `/money/new?party=<id>` с уже
    выбранным контрагентом. `back` проверяется `src/lib/back-path.ts` (только
    карточки, без открытого редиректа). Редактирования записей нет — «поменять»
    = отменить + записать заново.
23. **Позиции накладной** (`/documents/[id]`): вместо таблицы с вечно открытыми
    полями — список «название / qty ед × цена / сумма», правка по нажатию
    (`<details>`), расхождение qty×price с бумагой подписано прямо в строке.
24. **PDF накладной падал 500** — кириллица в `content-disposition`
    (ByteString). Теперь латинский `filename` + `filename*=UTF-8''…`.
25. **`/documents` — колонка «Кто»**: имя контрагента записи + «клиент» /
    «поставщик» (`partiesOf`, по запросу на таблицу, без N+1). Документ, не
    привязанный к записи, — «—».
26. **Итог дня — история** (`/day`): день по Бишкеку (00:00 UTC+6), будущие
    даты → сегодня. Для прошлого дня «Стало вечером»/«Долг на конец дня» =
    текущий баланс минус действующие движения после конца дня
    (`laterMovements`) — раньше показывался текущий долг. Выбор даты
    (`<input type=date>`) и таблица «По дням» за 14 дней (продано / собрано /
    приход). Снимок дня в БД по-прежнему не сохраняется — считается на лету,
    поэтому запись, отменённая позже, исчезает и из итога прошлого дня.
27. **`/documents/[id]` — новая раскладка**: сверху статус + предупреждения
    (тип документа, синоним контрагента), ниже фото | позиции рядом. Высоту
    ряда задаёт фото, позиции — `position:absolute` внутри панели и
    прокручиваются (`.doc-lines-*`); ≤900 px — друг под другом, позиции
    max-height 70vh. Для оплаты справа — данные чека.
28. **Многостраничные накладные** (миграция 11). Страница 1 — как раньше в
    `documents.storage_path`, страницы 2..N — в `document_pages` (данные
    существующих документов не переносятся — требование пользователя; каждый
    магазин видит только свои страницы: RLS + папка `<org>/` в
    `add_document_pages`). `documents.file_hash` многостраничного документа =
    `documentHash()` набора страниц (`src/lib/storage.ts`), поэтому
    create_document/дубликаты/кеш распознавания работают без изменений; у
    одностраничного хеш прежний. Форма: «Сфотографировать или выбрать» /
    «+ Добавить страницу», миниатюры с удалением, до `MAX_PAGES`=5
    (`src/lib/pages.ts`); при 2+ страницах ужимаем до 1600 px (все страницы
    идут одним запросом, лимит 4 МБ). Каждое изменение набора — новая проверка
    (новый документ и вызов Gemini; старые остаются свободными документами).
    Gemini получает все страницы одним запросом + `multiPagePrompt` (только
    при 2+ страницах; PROMPT_VERSION не менялся — одностраничный запрос тот
    же). Просмотр: `DocumentPhotos` — «Стр. 1 · 2 · 3». Чек оплаты — всегда
    одно фото. До применения миграции одностраничные записи работают, а
    многостраничная — ошибка «Не удалось загрузить фото».

## Практика (полезно повторить)

- На архитектурные развороты — план, особенно если меняется схема БД или
  основной поток данных; на неоднозначные продуктовые решения (блокировать
  или предупреждать, окно поиска и т.п.) — спросить пользователя
  (AskUserQuestion), а не решать самому.
- Баг из скриншота — **сначала Vercel runtime logs**: оба бага этой сессии
  (`invalid_supplier`, 23505 по `file_hash`, дубль `sales_organization_id_document_id_key`)
  были видны только в логах, а скриншот показывал вторичный симптом.
  После `redirect()` все поля формы визуально сбрасываются.
- Перед использованием конкретной версии/параметров внешней модели —
  проверять через WebSearch/WebFetch (ai.google.dev), не по памяти.
- Heredoc с кириллицей и кавычками в Bash-инструменте на этой машине
  (Windows, Git Bash) иногда ломается («unexpected EOF») — надёжнее писать
  Python-скрипт правок во временный файл через Write и запускать его.
- Пользователь коммитит/пушит сам (автокоммит) — не коммитить без просьбы,
  перед предположениями «надо запушить» проверить `git status`/`git log`.
