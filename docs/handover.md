## Что это

**Depter** — веб-приложение для магазинов стройматериалов в Кыргызстане:
цифровая тетрадь долгов клиентов и поставщиков с фото-основанием каждой
записи. Кодовое имя репозитория/пакета — `ongoy` (внутреннее, в интерфейсе
не показывается). ТЗ (обновлённая версия, Этап 1) лежит вне репозитория —
`C:\Users\erzha\Documents\ONOY\Depter — ТЗ, Этап 1.docx`; если нужно свериться
заново, читать через docx-скилл (Read не читает бинарные .docx напрямую).

Стек: Next.js 16 (App Router, TypeScript), Supabase (Postgres + Auth + Storage),
Vercel-деплой. Никакого service-role в приложении — всё через RLS и
security-definer RPC.

## Что сделано (в хронологии, все пункты — рабочие, protected by tests)

1. **Foundation** (до этой сессии): справочники, RLS, мультитенантность,
   `commit_purchase/sale/payment` — сумма долга вводится вручную, долг
   меняется сразу, без ожидания.
2. **Долги Этапа 1**: фото обязательно для прихода/продажи, необязательно
   для оплаты; сторно (отмена записи с комментарием, не удаление); заявки
   клиента «Я оплатил» + публичная страница `/c/[token]` без входа; итог дня
   (`/day`, живой пересчёт); акт сверки с печатью и PDF; напоминание —
   `wa.me`-ссылка.
3. **ADRE** (`src/lib/adre/`): распознавание фото через Gemini
   (`gemini-3.8-flash`), фон через `after()`, статусы документа
   (ожидает/распознаём/оцифрована/расхождение/ошибка), экран `/documents`.
   Ключ — только в Vercel Environment Variables и локальном `.env.local`,
   НЕ в Supabase (пользователь сначала просил перенести в Supabase Edge
   Function — сделали, потом попросили откатить обратно в Next.js; текущее
   состояние — в Next.js).
4. **Синонимы контрагента**: `src/lib/match.ts` (нечёткое сравнение имён,
   коэффициент Дайса, без pg_trgm) + баннер на `/documents/[id]`, если
   распознанное имя не похоже на выбранного контрагента.
5. **Оплата по квитанции**: синхронное распознавание чека до подтверждения,
   подсказка клиента по имени отправителя.
6. **Мгновенная сверка суммы прихода/продажи**: при выборе фото —
   распознавание сразу на той же странице (без сабмита/редиректа), сравнение
   с введённой суммой, кнопка «Подставить».
7. **Фирменный PDF**: `@react-pdf/renderer`, шрифт PT Sans (кириллица) в
   `public/fonts/`, регистрируется по HTTP (не `fs.readFileSync` — не
   гарантированно доступно в serverless-функции на Vercel).
8. **Нормализация извлечённых данных**: `src/lib/adre/normalize.ts` —
   разделитель дробной части (запятая→точка), единицы измерения к общему
   набору (шт/м/кг/упак/л), обрезка пробелов в названиях.
9. **Тип документа по ADRE**: показывается на `/documents/[id]`
   («накладная от поставщика» / «клиенту»), сверяется с тем, что выбрал
   продавец кнопкой — если не совпадает, предупреждение.
10. **Исправлен баг парсинга суммы**: `decimalInput` (`src/lib/validation.ts`)
    не понимал пробел как разделитель тысяч («54 270» — ровно то, как
    приложение само форматирует деньги) — сумма с пробелом отклонялась с
    невнятной ошибкой. Починено + добавлено логирование в оба места, где
    ошибка раньше проглатывалась молча (`commitOperation`).

## Сознательно не сделано / отложено

- Товары/склад (номенклатура) — код и таблицы существуют (products,
  inventory_movements), но скрыты из навигации Этапа 1. Пользователь сказал
  «потом сделаем» — это Этап 2, ждёт отдельного решения когда начинать.
- Второй AI-провайдер (Claude) как резерв к Gemini — интерфейс
  `RecognitionProvider` уже это позволяет, реализации нет.
- WhatsApp Business API (автонапоминания) — только `wa.me`-ссылки вручную.
- Вход по телефону + SMS/WhatsApp OTP + PIN — сейчас email/password.
- PDF накладной на публичной странице клиента (`/c/[token]`) — нужна ещё
  одна публичная RPC по токену, аналогично `get_statement_by_token`.
- Автоперенос реквизитов чека (`bank_reference`) в оплату — распознаётся,
  но не подставляется автоматически при оплате поставщику (только для
  клиента через отдельный поток «оплата по квитанции»).
- Подписка/биллинг, роли сотрудников, несколько точек в одном аккаунте.

## Проверки перед тем как считать что-то готовым

```bash
npm test          # PGlite — RLS, RPC, идемпотентность, ADRE SQL-слой, match.ts, normalize.ts, validation.ts
npm run typecheck
npm run build
```
34 теста, все зелёные на момент хендовера. Сетевые вызовы Gemini тестами не
покрыты (изолированы в одну функцию каждый раз) — проверяются вручную с
реальным ключом.

## Практика в этой сессии (полезно повторить)

- На архитектурные развороты — план через EnterPlanMode/ExitPlanMode,
  особенно если меняется схема БД или основной поток данных.
- Перед тем как чинить баг из скриншота — помнить, что после `redirect()`
  ВСЕ поля формы (включая file input) визуально сбрасываются на новой
  странице; скриншот "после" ничего не говорит о том, что было "до".
  Лучше проверять Vercel runtime logs (`get_runtime_logs`/`get_runtime_errors`)
  и добавлять `console.error` в места, где ошибка раньше проглатывалась молча.
- Перед использованием конкретной версии внешней модели (Gemini) —
  проверять актуальность через WebSearch/WebFetch, не полагаться на
  знания на момент обучения (было расхождение: `gemini-2.5-flash` уже
  устарела, актуальна `gemini-3.8-flash` на сентябрь 2026).
- Пользователь может сам коммитить/пушить параллельно с этой сессией
  (видно по git log — коммиты появляются без явного запроса от меня).
  Перед `git status`/предположениями "надо запушить" — сначала проверить
  реальное состояние.
